Ассистент по ⌘J работает с одной открытой заметкой — об этом статья [AI-ассистент в Drafta: ⌘J и ваш ключ](/ru/blog/ai-assistent/). Но агенту, который пишет со мной код, нужна вся библиотека: найти заметку об архитектуре, дописать в неё решение, завести новую для бага. Для этого в Drafta встроен MCP-сервер.

## Что такое MCP-сервер Drafta

MCP — протокол, через который AI-клиенты вызывают внешние инструменты. Сервер `drafta-mcp` лежит внутри самого приложения, в `Drafta.app/Contents/Helpers`. Ставить отдельно ничего не нужно.

Сервер даёт Claude Code, Claude Desktop, Cursor и другим MCP-клиентам доступ к вашим заметкам. Работает он с той же библиотекой Markdown-файлов, что и приложение.

## 12 инструментов

Пять инструментов читают:

| Инструмент | Что делает |
|---|---|
| `search_notes` | ищет заметки по тексту, тегу, блокноту и статусу |
| `read_note` | читает заметку целиком |
| `list_notebooks` | показывает блокноты |
| `list_tags` | показывает теги |
| `formatting_guide` | объясняет агенту, какой Markdown понимает Drafta |

Семь инструментов пишут:

| Инструмент | Что делает |
|---|---|
| `create_note` | создаёт заметку |
| `append_to_note` | дописывает в заметку |
| `update_note` | переписывает заметку |
| `set_note_status` | меняет статус |
| `tag_note` | ставит тег |
| `create_notebook` | создаёт блокнот |
| `trash_note` | отправляет заметку в корзину |

Инструмента, который удаляет заметку насовсем, нет. `trash_note` кладёт её в корзину, откуда её можно достать.

## Ревизия на каждую перезапись

Когда агент переписывает заметку через `update_note`, прежний текст сохраняется ревизией. Его видно в окне истории, и его можно вернуть одной кнопкой. Подробно об этом — в статье [История ревизий и резервные копии](/ru/blog/istoriya-reviziy-i-bekapy/).

`formatting_guide` нужен, чтобы агент писал заметки так, как их рисует Drafta: с callouts, диаграммами Mermaid, формулами, задачами и wiki-ссылками. Без него агент пишет плоский текст.

## Как подключить

В настройках есть раздел MCP. В нём две кнопки:

1. **Copy JSON config** копирует готовую конфигурацию для клиента, которому нужен JSON.
2. **Copy claude mcp add command** копирует команду для Claude Code.

Вставляете конфигурацию или команду в свой клиент — и агент видит библиотеку.

![Раздел MCP настроек: сервер drafta-mcp, переключатель Read-only, поле пути к библиотеке и кнопки Copy JSON config и Copy claude mcp add command](./mcp-server/mcp-settings.png)

*Раздел MCP: режим только для чтения, путь к библиотеке и две кнопки для подключения клиента.*

Поле Library задаёт, с какой библиотекой работает сервер. Если оставить его пустым, сервер берёт библиотеку по умолчанию. Кнопка Use current подставляет ту, что открыта в приложении.

## Режим только для чтения

Иногда агенту достаточно смотреть. Для этого есть переключатель Read-only: в этом режиме инструменты записи исчезают, и агент может только искать и читать.

> [!NOTE]
> Без действующей лицензии сервер работает только на чтение, даже если переключатель Read-only выключен. После триала без тарифа агент по-прежнему может искать и читать заметки.

## Как я этим пользуюсь

Проектная документация у меня живёт в Drafta: архитектура, чек-листы, решения. Агент в Claude Code перед работой ищет нужную заметку через `search_notes`, а после работы дописывает итог через `append_to_note`. Статус задачи он меняет через `set_note_status`, а не пишет «готово» в текст.

Эта серия статей тоже прошла через MCP-сервер: агент создал заметки в блокноте блога, а публикация на сайт сработала по статусу Completed.
